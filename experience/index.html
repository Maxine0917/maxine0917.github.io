2026.08 — 至今 · 交易应用产品经理

让 Agent 理解诉求，也能提供操作

当时的问题

退款咨询中，Agent 会误判意图，或只能解释却无法提供操作，商家仍需追问、转人工。

我负责的事

分析 1,308 条会话，推动意图、知识与操作卡片优化，参与退款 Workflow 与自主申诉链路。

关键判断

先分清商家想做什么，再补齐知识与工具。谈到退款，不等于同意退款。

项目结果

+18.31个百分点

售后咨询 Agent 参评解决率

5.56% → 23.87%

−4.62个百分点

售后咨询转人工率

14.80% → 10.18%

21 → 1单 / 日

退款申诉求助进线

新增商家申诉入口前后

前两项对应售后咨询 Agent 优化，第三项对应商家申诉入口，属于不同项目。

具体做法与复盘

具体做法

  • 把典型表达对应到真实意图

    按六类核心诉求整理会话，建立“表达—意图—处理路径”映射。将希望退款、希望拒绝退款、查询原因或进度等诉求分开，减少仅凭关键词选择路径。

  • 区分执行操作与咨询解答

    确定性的退款操作由 Workflow 处理，按“撤销核销 → 协商退 → 人工兜底”分级承接；售后咨询用 ReAct 组织知识与工具，根据具体诉求提供解释或操作入口。

  • 把回复延伸到可执行的操作

    补充异常退款规则与链接失效等知识，提供补充凭证等入口卡片；推动退款详情页新增自主申诉、进度查询与不可申诉原因展示。

我的复盘

不能把所有进线问题都交给客服解决。如果原因是产品功能缺失，话术和卡片只能缓解；要继续回到退款、申诉等业务链路补齐功能。

优化 Agent 时，我需要同时检查意图、知识、工具和处理结果。模型能否正确回复，很大程度上取决于它获得的业务信息是否充分。

美团 · Keeta

2026.04 — 2026.08 · 骑手履约产品经理

骑手能用，运营也能维护

当时的问题

中东骑手需要高温休息指引，巴西骑手关注接单收益；多国扩展需要可复用的配置能力。

我负责的事

负责休息站地图、接单卡片与上线点引导，以及官网和上下线规则的配置化设计。

关键判断

设计端上体验时，一起确认信息来源、运营维护与异常处理。

项目结果

+33个百分点

休息站上线后的骑手满意度

53% → 86%

−0.67分钟

被补贴商家的订单接单时长

2.49 分钟 → 1.82 分钟

实时配置生效

运营配置的上线方式

从依赖研发的天级流程转为自助配置

三项分别对应休息站地图、商户单单奖和配置化项目；不合并为同一项收益。

具体做法与复盘

具体做法

  • 休息站地图：从找到地点到维护信息

    选择列表与地图组合，提供入口、筛选和导航；后台支持批量导入、单点录入与生效状态维护，兼顾骑手查找和运营更新的成本。

  • 接单信息：让收益和出餐状态被看见

    在骑手接单触点展示商户单单奖与“出餐快”标签。对补贴呈现方案进行比较，关注接单时长、接单率与补贴成本，避免只看接单意愿而忽略成本。

  • 运营配置：把高频需求变成自助能力

    将官网内容、排班区域与上线点等配置开放给运营，设计批量操作、审批、生效时间与重复校验，让功能在跨国家复制时仍可维护。

我的复盘

休息站项目初期，我对当地路网数据质量的依赖评估不足。以后做地图相关需求，应先和数据、地图团队确认可用性，再决定交互方案。

配置化容易漏掉重复创建、冲突、生效时间和兜底场景；多语言文案也需要同步跟进。这些应在需求阶段一起梳理，减少中途修改。

2025.10 — 2026.03 · 直播营收产品运营

按主播分层，解决不同使用瓶颈

当时的问题

观众送礼点播表演时，中小主播有认知与配置门槛，头部主播则难以处理集中到来的指令。

我负责的事

结合行为、营收数据与直播切片，推动教育和配置引导，参与指令管理，协同 18 个区域团队落地。

关键判断

分清认知、配置和指令处理问题，再为不同主播设计方案。

项目结果

+2.16个百分点

指令礼物全球渗透率

1.15% → 3.31%

+0.60个百分点

指令礼物营收占比

0.23% → 0.83%

53% / 40%配置完成率

活动来源 / 常规来源

两种来源的用户配置完成情况比较

全球指标对应多轮迭代与推广后的变化，不归因于单次活动；配置完成率比较的是两种用户来源。

具体做法与复盘

具体做法

  • 让中小主播先了解，再完成配置

    设计“了解功能 → 访问页面 → 开播使用 → 获得营收”的任务链路，配合多语言教育内容和一键配置模板，降低开始使用的成本。

  • 为头部主播补充指令管理能力

    针对高并发下的漏单与排序问题，参与指令排队、优先点单的设计与推广，让主播能看清待处理的指令，并形成适配才艺场景的使用方式。

  • 按人群和时间段回看效果

    比较不同层级主播的使用与营收变化，同时关注活动结束后是否继续使用，区分短期激励和后续习惯。区域策略和垂类模板按市场调整。

我的复盘

同一个功能，不同用户的痛点可能完全不同。对中小主播做教育和配置引导，对头部主播做效率工具，比统一推广更有针对性。

活动期间的上涨不是全部结果。还需要回看活动结束后的使用和营收，结合分层对比，判断增长能否留下来。
